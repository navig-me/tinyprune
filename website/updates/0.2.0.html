TinyPrune 0.2.0

Choose Install Update to download, verify and install this release. TinyPrune will relaunch when it finishes. Your rules and settings are kept.

## What's changed

**Published prerelease.** Version 0.2.0 adds the Linux and Windows Rust runtime as a developer preview. macOS remains the only supported product; its app, agent, Finder extension, CLI and Sparkle updater are unchanged from 0.1.13 apart from the version number. Publication status, artifacts and verification evidence are recorded in [RELEASES.md](https://github.com/navig-me/tinyprune/blob/main/RELEASES.md).

- Align the Swift version defaults, all Rust crates and the Tauri shell at 0.2.0. Add `Scripts/check-versions.py` to CI, the authoritative `RELEASES.md` history, [ADR 0013](https://github.com/navig-me/tinyprune/blob/main/ADRs/0013-release-process-and-signing-custody.md) and the `.github/RELEASING.md` runbook.
- Simplify the landing page by removing its redundant introductory summary. Keep compatibility and licensing in the FAQ and download area. Update README, documentation and machine-readable references to distinguish published macOS downloads from the published Linux/Windows developer preview.
- Port rule matching, precedence, protection, configuration and scheduling decisions to Rust against 577 Swift-reference golden cases in 13 fixture files. Add Windows path and hidden-attribute handling with separate Rust-only tests.
- Add the Rust runtime ([ADR 0011](https://github.com/navig-me/tinyprune/blob/main/ADRs/0011-rust-runtime-store-scan-ipc-daemon-cli-ui.md)): SQLite stores, bounded metadata-only traversal, native Linux/Windows watchers, incremental scheduling, local socket/named-pipe IPC, daemon, CLI and a Tauri UI. The SQLite schema and IPC protocol are separate from the Swift app.
- Exercise native watchers, Trash/Recycle Bin adapters, daemon/CLI smokes, developer installs and the Windows managed updater in CI. Exercise the Tauri webview against the real agent in Linux Docker and Windows WebView2. These are developer checks, not general desktop or screen-reader acceptance.
- Reduce per-event work through incremental scheduling, and bound SQLite WAL checkpoint work between decision pages while retaining `synchronous=FULL`. Platform benchmark results and their limits are linked from the release log.
- Add the user-confirmed Rust updater ([ADR 0012](https://github.com/navig-me/tinyprune/blob/main/ADRs/0012-rust-runtime-signed-updates.md)): Ed25519-authenticated manifests, size-capped and SHA-256-verified artifacts, monotonic builds, staged installs, health checks, rollback and the Trash/update interlock. Linux Docker and Windows CI update tests use throwaway keys. The production-key Rust feed is deployed and its signature and archive hashes were independently verified; package-manager and hand-copied installs are not updated by it. macOS keeps Sparkle.
- Embed the production Rust update public key only in `rust-artifacts.yml` dispatch builds on `main`, never in pull-request builds. Production signing remains a separate reviewed release step using the existing key.
- Known limits: Windows config import/export is unsupported; Rust on macOS uses periodic reconciliation rather than a native watcher. POSIX rename and Windows Shell cannot atomically condition a move on file identity. Volumes without durable identity or creation time are re-observed after restart. Screen-reader acceptance, broad desktop testing and protected post-deployment verification remain outstanding.

## Install and trust

This preview is ad-hoc signed, NOT Developer ID signed, and NOT notarized. Download only from this repository and verify the SHA-256 checksum.

On macOS 15 Sequoia and macOS 26 Tahoe: copy TinyPrune.app into /Applications, try opening it once, dismiss the Gatekeeper alert, then open System Settings > Privacy & Security > Open Anyway. Confirm Open and authenticate if prompted. Control-click Open is not a substitute on these macOS versions.

If you deliberately trust this preview and Open Anyway is unavailable, run exactly:

    xattr -dr com.apple.quarantine /Applications/TinyPrune.app

Then open /Applications/TinyPrune.app again. This removes quarantine, not proof of safety; it does not notarize the app. Finder extension and launch-at-login may need separate approval in System Settings > General > Login Items & Extensions. Direct builds with a configured update public key support EdDSA-authenticated in-app updates; without that key, download updates manually. Homebrew updates only through the cask. EdDSA authentication is not Apple trust or notarization. Preview signing does not guarantee Finder extension or login-item activation on every Mac.
