Install TinyPrune

The first release is not published yet.

  1. Get the app

    When available, download TinyPrune.dmg from GitHub Releases and drag it to Applications. Or use Homebrew:

    brew install --cask tinyprune/tap/tinyprune

  2. Open it once by hand

    Early builds are not notarized. If macOS blocks the first launch, go to System Settings > Privacy & Security > Open Anyway. Alternatively, remove quarantine from the installed app:

    xattr -dr com.apple.quarantine /Applications/TinyPrune.app

  3. Allow the background agent

    TinyPrune offers to install its agent and sends you to Login Items to approve it. The agent does the work, so the app can stay closed.

  4. Add a folder and start in Preview

    Pick Downloads or a template. New rules start in Preview: you can review what would move to Trash without moving anything.

Until the first release, build from source with the Xcode command line tools:

git clone https://github.com/navig-me/tinyprune && cd tinyprune && swift Scripts/package-app.swift && open .build/package/TinyPrune.app

How it works

  1. 01

    Pick a folder

    Add a place for disposable files, such as Downloads or a screenshots folder.

  2. 02

    Set an expiry

    Match a name or pattern, then choose an age or a period of project inactivity.

  3. 03

    Review, then enable

    Check the matches in Preview. Enable the rule when you are ready for automatic moves to Trash.

Clean exactly what you want.

Choose the folder, what to match, and how old it should be. Project rules can wait until a project has been inactive, based on file timestamps.

  • Keep wins. A kept item, or a folder containing one, is protected from automatic cleanup.
  • Trash only. Put items back with Finder. TinyPrune has no permanent delete.

Useful rules to start with

Templates create ordinary rules you can edit or delete. These are examples, not folders TinyPrune monitors without your permission.

Example folders, matching items, and expiry times
FolderMatchMove to Trash after
~/Downloads*.dmg7 days
~/Downloads*.zip14 days
~/Desktop/ShotsScreenshots7 days
~/Developer/**node_modules30 days of project inactivity
~/Developer/**.venv45 days of project inactivity
~/Developer/**__pycache__7 days without modification

Keep overrides every rule, including these.

Every item says why.

Open a scheduled file to see the rule that matched, the timestamp used, and when it expires. Keep it or add 7 or 30 days if you need more time.

  • Finder extension: set Keep or an expiry from Finder.
  • Local history: review decisions and Trash operations in the audit log.
  • CLI: inspect and manage rules from your terminal.
