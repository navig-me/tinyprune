Documentation

A safer way to clear the things you no longer need.

TinyPrune gives folders and files a lifetime. It works locally and moves eligible items to the Mac Trash.

Project status

TinyPrune is in active development. Installation instructions will arrive with the first signed release.

Safety is part of every rule.

TinyPrune manages only the folders you choose. It records a stable filesystem identity for each root, then checks the current state again before any item moves.

Trash, not delete

Eligible items use the standard macOS Trash path.

Keep always wins

A Keep override takes precedence over every rule.

Local by design

Normal operation reads metadata only, with no account or cloud sync.

Rules describe a clear boundary.

Every rule establishes where to look, what to match, when it expires, and what happens next.

WHERE  ~/Developer/**
WHAT   Folder named node_modules
WHEN   Project inactive for 30 days
ACTION Move the folder to Trash

A rule can match files or folders by scope, depth, exact name, glob, age, modification time, project inactivity, or an explicit override.

Start in Preview.

Preview runs the same matching and scheduling logic, but does not invoke the Trash executor. It is the right way to test a broad rule before enabling it.

  1. Select a folder you control.
  2. Choose a template or build a rule.
  3. Review the upcoming items and their explanations.
  4. Add Keep or expiry overrides where necessary.
  5. Enable the rule when the result matches your intent.

Templates create ordinary rules.

Developer Cleanup, Downloads, Screenshots, Temporary Workspace, and Build Artifacts each create normal rules that you can edit, pause, duplicate, or delete. Developer templates and very broad folders such as your home folder always start in Preview. TinyPrune does not scan on demand: a new rule's matches appear in Upcoming after the agent indexes it, and the Rules screen shows scheduled matches and how many are already eligible.

Act from Finder.

The TinyPrune Finder menu can Keep an item, set an expiry (tonight, tomorrow, 7 days, 30 days, or a custom date), return an item to its folder rules, and explain why it will expire. Folders add Protect Folder, Set Folder Lifetime, and Create Rule. Each action is sent to the same background agent used by the app and CLI, so they always show the same resolved policy. The extension must be enabled in System Settings, and it only acts inside folders you have chosen to manage.

Inspect and script from the terminal.

The tinyprune command talks to the background agent. It has no cleanup engine of its own.

tinyprune status | rules | upcoming | activity
tinyprune keep invoice.pdf [--descendants]
tinyprune expire video.mov 7d        # also 12h, 30m, tonight, tomorrow
tinyprune inherit foo.zip
tinyprune why node_modules
tinyprune pause | resume
tinyprune config validate|preview|apply|export tinyprune.yml

Add --json for stable output; every document carries a schemaVersion. Config files are checked locally by validate, diffed against current rules by preview, and applied by apply only inside folders already managed in the app. Rules created from a config start in Preview unless you pass --active.

Updates follow the channel you choose.

Direct downloads will use a signed, notarized DMG and Sparkle update feed. Homebrew installs will use the TinyPrune cask, with Homebrew as the only updater for that channel.
