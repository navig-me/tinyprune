Install

The first release is not published yet.

You can build from source now. The download and Homebrew options below will be available once the release and tap are published.

Download or use Homebrew

When available, download the DMG from GitHub Releases and move TinyPrune to Applications. Once the tap exists, you can also install it with:

brew install --cask tinyprune/tap/tinyprune

Early builds are unsigned. On first launch, use System Settings > Privacy & Security > Open Anyway. Only open a build you trust. Alternatively, if you installed it in Applications:

xattr -dr com.apple.quarantine /Applications/TinyPrune.app

Build from source

With Apple's Swift development tools installed, run:

git clone https://github.com/navig-me/tinyprune && cd tinyprune && swift Scripts/package-app.swift && open .build/package/TinyPrune.app

Open the app, choose a folder you control, and add a template or your own rule. Start in Preview and review Upcoming before enabling cleanup.

What TinyPrune can change

TinyPrune only manages folders you choose. It reads filesystem metadata for normal operation, not file contents, and does not need an account or cloud service.

Items go to Trash

TinyPrune never permanently deletes files. Eligible items move to macOS Trash.

Keep wins

Keep overrides every expiry rule. A folder cannot be trashed if it contains a protected item.

Before each move, the agent checks the item's identity, current rules, protection, deadline, pause state, permissions, and volume availability again. The index schedules work; it does not authorize a move.

Pause and settings

Pause cleanup globally, for a managed folder, or for a rule. A timed global pause resumes when its time is up. In Settings, you can set the default grace period, protect hidden files, and choose how long to retain activity history. These settings apply to the app, Finder, and CLI.

Choose what expires and when

A rule specifies a folder, the files or folders to match, and the time basis for expiry. For example, you can target dependencies in inactive projects without expiring the source folder itself.

Match by exact name or glob, item type, and scope depth. Expiry can use age, modification time, or project inactivity. Set an explicit expiry on an individual item, use Keep to protect it, or choose Inherit to return it to the folder's rules.

Every decision includes an explanation: the matching rule, time basis, resolved deadline, project context when relevant, any override, and why an item is protected or skipped.

Check the matches before cleanup

A rule saved in Preview runs matching and scheduling without moving anything to Trash. Upcoming shows indexed candidates and their explanations.

  1. Choose a managed folder and create a rule.
  2. Use Preview matches in the rule editor for a read-only dry run. It is bounded and cancellable, and does not save changes or trash items.
  3. Review the matches, deadlines, and explanations. Add Keep or expiry overrides where needed.
  4. Enable the rule only when the result matches what you want.

The Rules screen also shows scheduled matches and how many are already eligible. These counts come from the index, so a newly saved rule needs time to be indexed.

Start with a template

Templates create ordinary rules you can edit, pause, duplicate, or delete. Pick a folder and adjust the match and lifetime to suit the files you actually keep there.

TemplateUse it for
DownloadsFiles that have outlived their usefulness in Downloads
ScreenshotsCaptures you only need briefly
Temporary WorkspaceDisposable files in a folder you choose
Developer CleanupGenerated dependencies in inactive projects
Build ArtifactsBuild output you can regenerate

Developer templates and very broad folders, such as your home folder, always start in Preview.

Use the Finder menu

Enable the TinyPrune Finder extension in System Settings. The menu works inside folders you have chosen to manage.

From Finder, you can Keep an item, set its expiry to tonight, tomorrow, 7 days, 30 days, or a custom date, return it to inherited rules, and ask why it will expire. Folders also offer Protect Folder, Set Folder Lifetime, and Create Rule.

Finder sends actions to the same background agent as the app and CLI. Folder lifetime, rule creation, and custom expiry open the app to finish the action.

Work from the command line

The tinyprune command talks to the background agent; it does not run a separate cleanup engine. Use it to inspect upcoming items, set overrides, or pause cleanup.

tinyprune status
tinyprune rules
tinyprune upcoming --json
tinyprune activity
tinyprune keep invoice.pdf --descendants
tinyprune expire video.mov 7d
tinyprune inherit foo.zip
tinyprune why node_modules
tinyprune pause
tinyprune resume

Expiry values also accept 12h, 30m, tonight, and tomorrow. Add --json for structured output; each document carries schemaVersion: 1.

Manage rules as code

tinyprune config validate tinyprune.yml
tinyprune config preview tinyprune.yml
tinyprune config apply tinyprune.yml
tinyprune config export

Config uses a restricted YAML format. validate checks it locally, preview compares it with current rules, apply saves the changes, and export writes the current configuration.

Apply only works inside folders already managed in the app, because the app must obtain folder access. Rules created from a config start in Preview unless you pass --active.

How updates will work

The release plan is a signed, notarized DMG with Sparkle updates for direct downloads. Homebrew installs will update through the cask only. Signing and notarization are not available in the current early builds.

For implementation details, read the contributor guide and release plan. Report problems or suggest improvements on GitHub.

Your files stay on your Mac.

No account, cloud sync, or file-content inspection in normal operation.
