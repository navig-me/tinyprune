TinyPrune documentation

File lifetimes, locally enforced.

TinyPrune is a macOS utility for assigning lifecycle rules to files and folders. It exists to manage disposable material without becoming a generic system cleaner.

Project status

TinyPrune is under active development. These docs describe the intended v1 behavior; download and installation instructions will be published with the first signed release.

Safety model

TinyPrune only operates on folders you select. It records a stable filesystem identity for each managed root rather than trusting a path alone. Before an item moves, the agent evaluates the current filesystem state again.

  • Trash, not permanent deletion. Eligible items move through the standard macOS Trash path.
  • Keep wins. An explicit Keep override takes precedence over every rule. A protected descendant blocks its parent from being moved.
  • Preview has no side effects. Preview evaluates matching, scheduling, and audit records but never invokes the Trash executor.
  • Local operation. Normal processing reads metadata only. TinyPrune does not require an account, cloud sync, or file-content inspection.

Rules

A rule answers four questions: where to look, what to match, when it expires, and what to do. Rules can match files or folders by scope, depth, exact name, glob, age, modification time, project inactivity, or an explicit override.

WHERE  ~/Developer/**
WHAT   Folder named node_modules
WHEN   Project inactive for 30 days
ACTION Move the folder to Trash

Rules can apply to an entire folder or to matching children. More specific rules and explicit item overrides resolve predictably. The inspector shows the matched rule, expiry basis, resolved deadline, and any condition suppressing an action.

Preview first

Start broad rules in Preview. This lets you inspect candidate items and explain why each one would be eligible without moving anything. TinyPrune uses this mode by default for broad developer-cleanup templates.

  1. Select a folder you control.
  2. Choose a template or create a rule.
  3. Leave it in Preview and review the upcoming list.
  4. Add Keep or expiry overrides where needed.
  5. Enable the rule only when the explanation matches your intent.

Updates and distribution

Direct downloads will use a signed, notarized DMG and Sparkle update feed. Sparkle updates are HTTPS-delivered and EdDSA-signed. The application will not install an update while it is actively processing a Trash operation.

Homebrew installs will use the TinyPrune cask. Homebrew is the sole updater for that channel; Sparkle automatic update checks are disabled in its build.

Development

The repository contains the product specification and staged implementation plan. Contributions must preserve the policy invariant: the database schedules candidates but never authorizes a Trash operation. See CLAUDE.md for contribution constraints and PLAN.md for the release architecture.
