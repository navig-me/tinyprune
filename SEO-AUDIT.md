# TinyPrune SEO and AI discovery audit

Audit date: 2026-10-20. Scope: `tinyprune.com`, `docs.tinyprune.com`, and the public `navig-me/tinyprune` GitHub repository. This records observed findings, repository fixes, verification, and work that requires publishing or account access. It is not a claim of ranking, indexation, or AI-citation improvement.

## Assessment

The foundation was already sound: substantive static HTML, English language declarations, HTTPS, canonical URLs, social cards, JSON-LD, public robots policies, sitemaps, self-hosted fonts, and links between the product, docs, and GitHub. The highest-priority defect was both published sites returning HTTP 200 HTML for nonexistent paths. Product facts were less consistent than the technical foundation: stale release references, a contradictory README update description, and important landing examples/documentation anchors that depended on JavaScript.

No runtime logic, platform adapters, release workflows, or recorded native verification results were changed. The macOS guide describes the Swift app on macOS 14+, Intel and Apple silicon. Public Windows/Linux availability wording points to platform-specific GitHub Releases and installation requirements rather than embedding a release-status label in evergreen SEO content.

## Checks that were already healthy

- HTTP apex requests redirect to HTTPS (observed 301).
- Both root pages expose meaningful content and metadata in initial HTML.
- Robots policies permit public crawling; no discovery-versus-training permission changes were made. Comments now distinguish their purposes.
- Landing JSON-LD was confirmed in a real browser, not inferred absent from text extraction. Documentation contains TechArticle and FAQPage semantics.
- Navigation, downloads, first-launch guidance, safety, rules, templates, CLI, support, licensing, and platform status are public and linked.
- GitHub API inspection confirmed a public MIT repository with a useful description, homepage `https://tinyprune.com`, and 20 relevant topics. These settings were left unchanged. `has_pages` is false: the public sites are Cloudflare Pages, not a separate GitHub Pages deployment.
- Published websites and GitHub README distinguish app telemetry from website analytics.

## Content ownership and programmatic SEO decision

Keep the current landing page and one comprehensive canonical documentation guide. The short install/rules/CLI sections and safety-dependent template table do not justify duplicate standalone pages merely to create indexable URLs. Fragments provide navigation within the guide; they are not represented as independently indexed pages in the sitemap.

| Query / fact family | Owning location | Reader value |
|---|---|---|
| TinyPrune; automatic file cleanup rules for macOS | `https://tinyprune.com/` | Definition, screenshots, demo, download |
| TinyPrune price, supported platforms, privacy | `https://tinyprune.com/#faq` | Free MIT license, actual release support, limits |
| Install TinyPrune; Homebrew; Gatekeeper | `https://docs.tinyprune.com/#install` | Commands, first-launch approval, agent setup |
| Preview cleanup; protect files; restore from Trash | `https://docs.tinyprune.com/#preview` and `#safety` | Review workflow and honest recovery limits |
| Expire Downloads, screenshots, node_modules, build output, caches | `https://docs.tinyprune.com/#templates` | First-party template defaults and risks |
| Glob matching; age versus project inactivity | `https://docs.tinyprune.com/#rules` | Matching boundaries and explanations |
| AI coding-agent scratch folders, logs, worktrees | `https://docs.tinyprune.com/#agents` | Deliberate scopes, preservation and worktree cautions |
| TinyPrune CLI, JSON, config | `https://docs.tinyprune.com/#cli` | Commands, exit codes, permission prerequisites |
| Update trust and installation | `https://docs.tinyprune.com/#updates` | Sparkle/manual/Homebrew distinctions |
| TinyPrune source and engineering status | `https://github.com/navig-me/tinyprune` | Source, license, releases, platform verification matrix |

Only expand into separate guides when each offers substantial independent instructions, first-hand examples, distinct risks, and maintained product data. Do not generate OS keyword variants before those OS releases exist, or mass-produce cache/tool pages by swapping names. Search volume and competitive demand were not measured; no forecast is implied.

## Publishing and external follow-through

1. Publish both sites **only** through `.github/workflows/deploy-pages.yml` with the existing reviewer-protected GitHub Environment. It uploads the whole directories, including new 404 pages. No workflow or credentials changed.
2. After publishing, recheck both root URLs, robots, sitemaps, llms, absolute cross-site links, and unknown-path HTTP 404 responses. Confirm no production CDN/WAF rule challenges legitimate search crawlers; permissive robots alone does not prove IP-based access.
3. In verified Google Search Console and Bing Webmaster Tools, submit `https://tinyprune.com/sitemap.xml` and `https://docs.tinyprune.com/sitemap.xml`. Inspect the canonical roots and request recrawling after release. No authenticated webmaster data was available during this audit.
4. Capture a real mobile Lighthouse run and available CrUX/Search Console field data. Measure before changing image/font formats or analytics loading, and preserve screenshot legibility and typography.
5. If desired, configure `www` DNS/TLS and an apex redirect in Cloudflare. Do not create a second canonical host.
6. Keep GitHub description/topics, Homebrew metadata, and genuine third-party profiles aligned with platform-specific releases and positioning. Keep native verification claims tied to recorded checks. Do not fabricate reviews or create an artificial Wikipedia footprint.

## Discovery baseline and monitoring

Two public search probes were run: `"TinyPrune" macOS file cleanup` and `site:tinyprune.com OR site:docs.tinyprune.com "TinyPrune"`. The documentation root appeared in the returned results. The small result set does not establish complete indexation, rank, traffic, or AI visibility. No authenticated Google AI Overview, ChatGPT, Perplexity, or other engine citation baseline was available.

Track these ten intent families, using natural wording variants rather than publishing ten thin pages:

1. What is TinyPrune and how does it work?
2. How can I automatically clean Downloads on a Mac without permanent deletion?
3. How do I expire screenshots on macOS?
4. How do I clean node_modules only after project inactivity?
5. How do I preview file cleanup and protect files I need?
6. How do I clean coding-agent scratch folders and logs?
7. Can I safely clean Git worktrees with TinyPrune?
8. Is TinyPrune free and does it work offline?
9. How do I install TinyPrune with Homebrew and approve first launch?
10. Does TinyPrune support Windows or Linux?

For each supported search assistant, run each intent 3–5 times under recorded conditions (engine/version, date, market, language, search enabled). Record retrieved/cited URL, brand mention, actual recommendation, competitors, factual errors, and sample size separately. Repeat monthly. A citation is not a recommendation. Prioritize correcting wrong price/platform/safety facts on the owning page before adding content. Track Search Console impressions/clicks/indexation, existing website referral and download-click events, and delayed branded traffic without inventing causal attribution. No application telemetry was added.
